# งาน Codex: แก้กล่องรุ่น 2 แบบคล้องคอ ให้พร้อมสั่งพิมพ์

## เป้าหมาย
แก้แบบกล่องรุ่น 2 **เฉพาะแบบคล้องคอ (pendant)** ให้ตรงกับผลจำลองการแกว่ง ชิ้นส่วนที่ซื้อจริง และข้อจำกัดของการพิมพ์ FDM แล้ว export STL ชุดใหม่สำหรับส่งร้านพิมพ์

ขนาดชิ้นส่วนบางตัวยังไม่ได้วัดด้วยเวอร์เนียร์ จึงต้อง:
- รวมค่าที่ยังรอวัดไว้ในที่เดียวใน `config.js`
- ทำให้แก้ค่าเหล่านี้แล้ว `node work/build.mjs` ครั้งเดียว ได้ STL ใหม่ทันที

## อ่านก่อนเริ่ม
- `case3d/work/config.js`, `model.js`, `shell-geometry.js`, `print-model.mjs`, `export-print.mjs`, `build-print-handout.mjs`
- `case3d/sim/pendant-sim.mjs`: ฟังก์ชัน `device()` บอกตำแหน่งจุดร้อยเชือกของแบบ E ที่ใช้ในการจำลอง
- Skill ใน `.agents/skills`: `dfam-check` (ตรวจ STL) และ `threejs-geometry` (ถ้าต้องสร้างรูปทรงใหม่) ส่วนโปรเจกต์ใช้ three **0.180** ให้ใช้เฉพาะ API ที่มีใน r180

## สิ่งที่ต้องแก้

1. **ใช้แบตใหม่:** เพิ่มขนาดแบตใหม่ใน `batteries` แล้วตั้งให้ทั้งแบบคล้องคอและการ export STL ใช้ขนาดนี้
2. **ช่องเผื่อและโฟม:**
   - ระยะเผื่อของบอร์ดรอบขารอง (`v2.ledge.lipGap`): เปลี่ยนจาก 0.3 เป็น 0.8 มม. ต่อข้าง
   - ช่องแบต: เผื่อรอบละ 1.5 มม. ให้โฟม 2 มม. ยุบเหลือ 1.5 มม. แล้วรัดแบตแบบนุ่มๆ
   - ผนังกันการ์ด SD (`v2.sdStop.foam`): เปลี่ยนเป็น 2.0 มม. ให้โฟมแตะปลายการ์ดพอดี แต่ไม่ดันการ์ด
3. **ยึดเชือกแบบสองรู (ตามแบบ E ในผลจำลอง):**
   - **เอาออก:** ห่วงเดียวกลางขอบบน
   - **ใส่แทน:** ห่วงเล็ก 2 อัน ที่มุมบนของฝาหลัง จุดกลางรูอยู่ที่ x = ±18 มม.
   - **ตำแหน่ง:** ผิวด้านหลังของห่วงเสมอกับผิวหลังกล่อง ห่วงยื่นเหนือขอบบน
   - **รู:** Ø3.5 มม. แกนรูชี้ตามแกน z (หน้า-หลัง) แบบเดียวกับห่วงเดิม
   - **ความหนา:** เนื้อรอบรูหนาอย่างน้อย 1.6 มม. ทุกทิศ
   - **ห้ามชน:** สกรูมุมบน
   - **วิธีร้อยเชือก:** รูซ้าย → พาดข้ามขอบบน → รูขวา
4. **แผ่นกันลื่นด้านหลัง:** ทำร่องตื้นลึก 0.5 มม. ขนาด 30 × 50 มม. ที่ผิวหลังของฝาหลัง ตรงตำแหน่งแบต ไว้วางแผ่นยาง ไม่ต้องพิมพ์แผ่นยาง
5. **สกรูหัวเตเปอร์:**
   - **ฝาหน้า:** ทำรูกรวย 90° ปากกว้าง Ø4.0 มม. ให้หัวสกรูจมเสมอผิวหรือลึกกว่าผิวไม่เกิน 0.2 มม. รูทะลุ Ø2.4 มม.
   - **เสาในฝาหลัง:** รูนำ Ø1.7 มม.
   - **ความยาวสกรู 16 มม.:** ปลายสกรูต้องห่างผิวหลังด้านนอกอย่างน้อย 1.0 มม. ถ้าไม่ได้ ให้ใช้ความยาวอื่นที่มีในชุด แล้วเขียนไว้ในรายงาน
6. **ปุ่มสูง 7 มม.:**
   - ปรับตำแหน่งปุ่ม (`button.switchZ`) และฝาปุ่มให้กดได้ คือฝาปุ่มยื่นจากผิวหน้าประมาณ 1 มม. และกดลงไปถึงสวิตช์ได้
   - ระยะที่ปุ่มจมลงได้ต้องไม่น้อยกว่าระยะกดของสวิตช์ (ประมาณ 0.3 มม.)
7. **ผนังที่บางเกินสำหรับ FDM:** ในชิ้นของแบบคล้องคอ ทุกจุดต้องหนาอย่างน้อย 1.2 มม.
   - **ท่อไมค์:** ผนังเดิม 0.5–0.6 มม. ให้หนาขึ้น หรือเปลี่ยนเป็นรูตรงทะลุผนัง
   - **lip:** เดิม 0.9 มม.
   - **ฝาปุ่ม:** เดิม 0.7 มม.
8. **กล้องก้มลง:** ผลจำลองบอกว่าตอนกล่องพิงอก ฝาหน้าเงยขึ้นประมาณ 11–16° จึงต้องให้กล้องก้มลงจากแนวตั้งฉากกับฝาหน้า **12°**
   - ถ้าค่า tilt เดิมรองรับแค่การเงย ให้ทำให้รองรับค่าติดลบด้วย
   - ช่องรับภาพ (aperture) ต้องไม่บังมุมมองภาพ (FOV)
9. **ช่องบอร์ด USB-C:** ยังไม่รู้ขนาดบอร์ด
   - ทำเป็นช่องหลวม ขนาดภายใน 16 × 14 มม. ไม่มีผนังด้านหลัง ยึดบอร์ดด้วยกาวร้อนตอนประกอบ
   - ช่องเสียบสายด้านล่างกล่องขยายเป็น 12 × 5 มม. เผื่อตำแหน่งหัว USB คลาด
   - เขียนไว้ใน handout ว่าให้จัดหัว USB ให้ตรงช่องก่อนหยอดกาว
10. **แบบคลิปและแม่เหล็ก:** เก็บไว้ให้ build ได้ แต่ไม่ต้อง export สำหรับพิมพ์รอบนี้

## Export และตรวจ
1. **สำรองไฟล์ก่อนแก้:** คัดลอก `case3d/work` และ `case3d/print/v2` ไปไว้ที่ `_backup/case3d_before_pendant_r2_20261023/`
2. **Export ไปที่ `case3d/print/v2/`:** เฉพาะชิ้นของแบบคล้องคอ ได้แก่ ฝาหน้า ฝาหลังแบบคล้องคอ ฝาปุ่ม และชิ้นทดสอบขนาด (fit coupon) แล้วอัปเดต README, handout และ manifest ให้ตรงกับชิ้นที่ export
3. **ตรวจ STL ทุกไฟล์ด้วย dfam-check:** ใช้ Python ที่ติดตั้งไว้แล้ว ห้ามติดตั้งใหม่

   ```
   "D:\ADONO\Memory Clip\.venv-dfam\Scripts\python.exe" "D:\ADONO\Memory Clip\.agents\skills\dfam-check\scripts\dfam_tool.py" measure <stl> --angle-limit 45
   ```

   ต้องผ่าน 2 ข้อ:
   - ไฟล์ปิดสนิท: `mesh.watertight` เป็น `true`
   - ผนังหนาพอ: `wall_thickness.per_body[].p05_mm` ทุกค่า ≥ 1.2 ถ้ามีจุดที่ต่ำกว่าแต่จำเป็นต้องบางจริง (เช่น ร่องแผ่นยาง) ให้เขียนเหตุผลไว้ในรายงาน
4. **รันเทสต์ทั้งหมด:** `node work/verify.mjs` จาก `case3d/` ต้องผ่านทุกชุด ถ้าเทสต์เดิมเขียนค่าตัวเลขเก่าตายตัวไว้ (เช่น ความสูงกล่อง 90 มม.) ให้แก้เทสต์ให้คำนวณจาก CONFIG แทน ห้ามลบเทสต์ทิ้ง
5. **ถ้างานแอนิเมชันการห้อยคอเสร็จแล้ว:** ห้ามทำให้โหมดนั้นพัง

## เกณฑ์ว่าเสร็จ
- ทำครบทุกข้อในหัวข้อ "สิ่งที่ต้องแก้" ทั้ง 10 ข้อ
- `verify.mjs` ผ่านทุกชุด
- ผล dfam-check ของทุกไฟล์ STL ที่ export อยู่ในรายงาน
- **รายงานภาษาไทย** ต้องมี:
  - ไฟล์ที่แก้
  - ขนาดกล่องใหม่ (กว้าง × สูง × หนา)
  - น้ำหนัก PLA โดยประมาณ
  - ตารางผล dfam-check ของแต่ละไฟล์
  - ความยาวสกรูที่เลือก
  - รายชื่อค่าใน CONFIG ที่ต้องแก้หลังวัดด้วยเวอร์เนียร์
  - สิ่งที่ยังไม่ได้ทำ
